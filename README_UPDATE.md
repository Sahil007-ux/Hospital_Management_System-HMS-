# HMS schema synchronization — 2026-10-15

این بسته فقط فایل‌های اصلاح‌شدهٔ پروژه است؛ پروژهٔ کامل یا دیتابیس دارای دیتا نیست.

## جایگزینی فایل‌ها

1. از فولدر فعلی پروژه یک کاپی پشتیبان بگیر.
2. محتویات این بسته را در ریشهٔ پروژه کاپی کن؛ فایل‌های هم‌نام را جایگزین کن.
3. فولدر migration/Migrations و فایل Schema/HMS_Current_Schema.sql اصلی را نگه دار. تاریخچهٔ migrationها در این بسته تغییر نکرده است.
4. فعلاً هیچ فایل SQL را روی دیتابیس فعلی اجرا نکن. جایگزینی فایل‌ها خودش دیتابیس را تغییر نمی‌دهد.

## ساخت یک دیتابیس جدید در آینده

1. در SSMS یک دیتابیس خالی با نام جداگانه، مثلاً HMS_Verification، بساز.
2. فایل migration/_Master_Query.sql را باز کن و دیتابیس تازه را در فهرست بالای SSMS انتخاب کن.
3. فقط Master Query را اجرا کن. فایل‌های جداگانه برای مطالعه‌اند؛ پس از Master دوباره اجرا نشوند.
4. migrationهای تاریخی را پس از Master اجرا نکن؛ تغییرات آن‌ها در ساختار فعلی موجود است.
5. برای دیتابیس فعلی نیاز به اجرای Master یا migrationهای قبلی نیست.

## چه چیزهایی هماهنگ شد؟

- Master Query از Schema ارسالی ساخته شد: ۱۹ جدول، ۹ Trigger، یک View، کلیدها، روابط، Indexها، Defaultها و Checkها.
- فایل‌های جداگانهٔ جدول‌ها و Foreign Keyها با نام‌های فعلی هماهنگ شدند. فایل‌های جدول فقط قطعهٔ ساخت جدول‌اند؛ نصب کامل توسط Master انجام شود.
- مسیرهای مخصوص درایو E، CREATE DATABASE و تنظیمات سطح دیتابیسِ خروجی SSMS از Master حذف شدند؛ کاربر دیتابیس مقصد را انتخاب می‌کند.
- دیتای نمونه یا تغییر جدید در طراحی اضافه نشده است.

## بررسی انجام‌شده و محدودیت

تعریف اشیای Master با بدنهٔ Schema ارسالی مقایسه شد و ترتیب خروجی SSMS حفظ شد. این بسته روی SQL Server اجرا نشده؛ موفقیت نصب در دیتابیس خالی هنوز باید بررسی شود. آزمایش‌های قبلیِ شما جای آزمایش نصب این Master را نمی‌گیرد.

بعضی نام فایل‌های تاریخی مانند 22_Standardize_Column_Names_Fixed (1).sql حفظ شده‌اند. تغییر نام آن‌ها برای کارکرد دیتابیس لازم نیست.
